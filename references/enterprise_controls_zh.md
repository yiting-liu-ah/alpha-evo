# 企业级量化研究控制标准

## 目录

1. 权限与数据分级
2. 研究完整性
3. 模型与 Prompt 治理
4. 统计控制
5. 风险与可交易性
6. 变更、审计与恢复

## 1. 权限与数据分级

将数据分为：公开 Skill 资产、内部研究配置、机密 Alpha 资产、凭据与 Session。公开文件不得包含后三类内容。

模拟和提交属于外部状态写入，必须获得用户明确授权。本项目已获持续自动提交授权；程序只对`grade ∈ {AVERAGE, GOOD, EXCELLENT, SPECTACULAR}`且IS Tests无`FAIL`的候选尝试提交，`PENDING`交由服务器解析，并保存最终状态。

## 2. 研究完整性

- 预先登记 Region、Universe、Delay、预算、方向、阈值、停止条件和压力窗口。
- 记录全部候选、失败、修复和 API 调用。
- 进化只使用允许的样本内指标和 ACTIVE Self-correlation。
- 隐藏测试、竞赛分数和最终迁移结果不得反馈到候选生成。
- 任何手工改写必须生成审计事件。

## 3. 模型与 Prompt 治理

- 记录 Agent Runtime、模型、Prompt 版本和候选 Schema 版本；平台无法自动提供时，在外部实验清单记录。
- 消融组使用同一模型、Prompt 版本、候选预算、迭代预算和指标政策。
- 不允许模型在看到结果后修改奖励、门槛或停止条件。
- 经验晋升必须有人审阅，并保留样本数、反例和适用范围。

## 4. 统计控制

- 使用独立 Run ID 执行至少 3 个 Seed 的方法比较。
- 披露候选总数、修复数、失败数和搜索空间。
- 当差异小于跨 Seed 波动时，禁止声称组件有效。
- 显著性主张需在外部使用 HAC、Block Bootstrap、Reality Check、SPA、FDR 或 Deflated Sharpe 等合适方法。
- 最终测试必须保持未触碰；不得用测试表现决定停止迭代。

## 5. 风险与可交易性

- 分解行业、市值、Beta、波动率、流动性和拥挤暴露；BRAIN 未直接提供时在外部研究平台补充。
- 同时审查 Sharpe、Fitness、Returns、Turnover、Drawdown、Margin、多空数量和全部 IS Checks。
- 计算与全部 ACTIVE Alpha 及池内成员的按日期对齐每日 PnL 相关性。
- 资本配置前完成费用、滑点、成交限制、容量、冲击成本、借券和极端行情测试。
- BRAIN 提交通过只代表平台门槛，不代表生产级投资批准。

## 6. 变更、审计与恢复

- 轨迹历史只追加，不覆盖。
- 每次发布前运行 Self-test、治理审计、Skill Validator 和本地链接检查。
- API 请求达到预算、认证失效或结果不确定时停止，不盲目重试 POST。
- 私有运行可以从 JSONL 和 `run.json` 恢复；不得依赖聊天上下文恢复。
- 发现 Hash、谱系、奖励或 PnL 日期不可重算时，将运行标记为 FAIL。

## 7. 发布门槛

只有同时满足以下条件才能进入真实提交候选集：

1. 软件验证、治理审计和全部研究门控通过。
2. 假设与数据语义一致且具有清晰反例。
3. 研究结果在独立运行、年度和预设压力期内具有可接受稳定性。
4. 多重检验和搜索预算已披露。
5. 相关性、成本、容量和风险暴露符合机构政策。
6. 用户已明确批准本项目自动提交，并保留`--no-auto-submit`诊断退出开关。

只有外部生产评审通过后，才能讨论资本配置。
