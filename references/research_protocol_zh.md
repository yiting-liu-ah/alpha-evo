## 1. 研究目标与边界

将一次端到端研究尝试定义为一条轨迹：

`市场上下文 -> 假设 -> 语义规范 -> FastExpr -> 设置 -> 模拟 -> 评价 -> 决策`

优化轨迹的预期终端奖励，而不是单个回测指标。进化过程只能使用 BRAIN 样本内指标和 ACTIVE Alpha Self-correlation。隐藏测试、竞赛或提交结果只能用于最终审计，不得反馈给候选搜索。

本 Skill 为 BRAIN 生成公式 Alpha。它无法复现论文中的 LightGBM 因子池模型或 TopkDropout 组合，因为这些不属于 BRAIN FastExpr 接口。应将对应思想映射为受控 Alpha 池、平台中性化、Truncation、Turnover、Margin 和 Self-correlation，不得声称实现等价。

## 2. 轨迹契约

用 `candidate_schema.json` 表示每个候选，强制要求：

- 可以被证伪的经济机制；
- 预期方向和周期；
- 支持每项叙事主张的可观测字段代理；
- 明确的失败模式；
- 一个 FastExpr 表达式和完整模拟设置；
- 操作类型和父节点谱系。

将私有轨迹保存在 `private/research_runs/<run-id>/`。禁止把原始 Alpha ID、表达式、PnL、凭据或账户状态写入 `SKILL.md` 或公开 references。

## 3. 规划与因子实现

从 10 个互补方向开始：盈利质量、基本面变化、现金流与应计、估值、分析师修正、投资效率、价量微观结构、波动率与期权、新闻与情绪、状态条件复合信号。

每个假设最多生成 3 个表达式。机制、数据类别、周期和市场状态必须具有实质差异。禁止把仅改变参数的表达式当作差异化规划。

按四个阶段实现假设：

1. 从本地 USA TOP3000 Delay 1 字段目录选择字段。
2. 说明每个字段如何观测经济机制的某一组成部分。
3. 构造受限 FastExpr 和设置对象。
4. 在任何 API 请求前执行确定性验证。

将解析后的 Token 结构作为兼容 BRAIN 的符号表示。通过 BRAIN Simulation 端点完成编译。语法、算子签名或单位错误最多允许两次实现修复；修复时保持经济假设冻结。编译错误不得成为修改经济假设的理由。

## 4. 确定性门控

模拟前执行全部门控：

- 表达式长度不超过 250 个字符。
- 基础字段不超过 6 个。
- 括号深度不超过 12。
- 数值自由参数占“数值参数与算子调用之和”的比例低于 50%。
- 字段存在性：每个标识符必须解析为目录字段、已验证算子或保留关键字。
- 类型安全：VECTOR 字段必须通过已验证的向量归约处理。
- 语义一致性：表达式中的每个字段必须出现在 `observable_proxies`；每个必需代理必须出现在表达式。
- 主张证据：分析师、期权、新闻、社媒或基本面主张必须至少使用一个对应类别字段。
- 结构新颖性：抽象 Token n-gram 与字段 Jaccard 的加权相似度必须低于 0.90。
- 表达式不得包含自相关恒等式、可直接约掉的代数链或不合法父节点谱系。

模拟后，在按日期对齐的每日 PnL 变化上执行功能冗余控制。提交前必须覆盖全部 ACTIVE Alpha，每对至少有 50 个共同日度变化；任一 PnL 不可用或重叠不足时失败关闭。与任一 ACTIVE Alpha 或已选因子池成员的绝对相关性达到 0.70 时拒绝候选。改变窗口、权重、Decay 或 Neutralization 本身不能证明新颖性。

## 5. 评价与奖励

用 BRAIN 指标同时评价预测质量和交易质量：

- Sharpe 和 Fitness：风险调整后的有效性；
- Returns 和 Margin：收益与交易效率；
- Turnover：交易摩擦敏感度；
- Drawdown：路径风险；
- IS Checks：集中度、子样本稳健性、换手和 Self-correlation；
- ACTIVE 每日 PnL 相关性：增量组合价值；
- 表达式复杂度：可解释性和过拟合控制。

使用 `research_core.trajectory_reward` 中的确定性奖励：

`0.30 Sharpe + 0.25 Fitness + 0.15 Returns + 0.10 Novelty - 0.08 Drawdown - 0.07 Turnover - 0.05 Complexity - 0.10 per failed-gate tier`

每个分项均按已记录阈值缩放并截断。Novelty 优先使用 ACTIVE 日度 PnL 相关性；PnL 不可用时使用 AST/字段结构新颖性，禁止把未提交候选统一记为满分。必须保存分项明细。禁止 LLM 在看到结果后重新定义奖励。

## 6. 变异与交叉

### 变异

修改候选前先定位失败：

- 语法或单位错误：冻结假设与代理，只修复实现。
- 权重集中：冻结机制，修复回填、排序、缩尾或 Truncation。
- 高换手：从周期、Decay或交易条件中只改一项。
- 低换手：缩短周期或换活跃代理，只改一项。
- 低 Fitness：先判断换手还是收益弱，再修一个原因；不得默认继续平滑。
- 低子样本 Sharpe：从分组、中性化或流动性依赖中只改一项。
- 低 Sharpe：从字段、窗口或分组中只试一项。
- 高相关：修改一个相关信号腿、一个代理或一个有实际含义的状态过滤；不得只调参数。

Mutation父代覆盖全部历史已评价的非ACTIVE轨迹，并按已记录奖励直接排序。不使用mechanism cluster配额、lineage root上限、失败距离、选择档位、父代使用次数或固定路线比例。每个任务只生成一个子代。

选中父代后，任务保存真实失败原因、本次保留内容、本次唯一修改、过去action及其结果。候选生成必须消费反馈卡，禁止按iteration选择预写公式，也不得重复已经使同一父代变差的 `action_id`。评价后保存相对父代的指标变化、已解决失败和新引入失败。

一次子代变差只否定本次修改，不否定父代。不得关闭、淘汰或永久降格父代；同一父代以后可以尝试不同修改。高相关也不得自动把局部修复升级成全面更换机制。

### 交叉

从已评价轨迹选择父节点并合成一个连贯子假设。不得按机制簇或血缘设置配额，不得复制完整ACTIVE表达式、机械拼接或平均。最终子代仍接受静态门控和实际PnL相关性检查。

初始多样化规划只执行一次。后续每组20次固定拆成 `14 Mutation → 评价 → 6 Crossover`：14个Mutation任务各生成一个子代；完成登记、Simulation和轨迹评价后，才生成Crossover任务包。不设置12/2等额外路线配额。

## 7. 因子池治理

每次迭代后维护累计因子池：

1. 只保留通过静态门控和指标门控的候选。
2. 按确定性轨迹奖励降序排序。
3. 逐个接纳与所有池内成员结构相似度低于 0.90、每日 PnL 绝对相关性低于 0.70 的候选。
4. 默认将池大小限制为合格候选总数的 50%，且最多 150 个。

默认执行 5 次迭代，收敛研究最多允许 15 次。连续 3 次迭代没有显著最佳累计改善，或新增候选降低回撤/新颖性表现时提前停止。将论文中“第 11-12 次较优”的观察视为待检验假设，而不是通用停止规则。

## 8. 非平稳性、迁移与压力测试

执行年度每日 PnL 变化诊断，识别 Alpha 衰减和状态依赖。使用 `analyze_run.py` 生成年度结果和用户指定的压力窗口。PnL 单位诊断不是收益率，必须正确标注。

执行 Universe 或 Region 迁移时：

1. 在查看目标结果前冻结源表达式和假设。
2. 验证目标 Region、Universe、Delay 中的每个字段和算子。
3. 只修改平台必需设置。
4. 分别记录迁移部分和重新拟合部分。
5. 字段、表达式或模型权重在目标市场重新优化后，禁止称为 Zero-shot。

BRAIN 公式模拟不提供论文的 TopkDropout 成本模型，因此只能通过 Turnover 和 Margin 评价交易摩擦。没有明确平台指标或外部执行回测时，禁止宣称交易成本稳健。

## 9. 统计与操作控制

- 记录每个尝试，包括门控失败和模拟失败。
- 记录搜索预算：研究方向、候选数、迭代数、API 调用数和修复次数。
- 使用多个独立种子/运行比较消融；当单次差异小于运行间波动时，不得作因果解释。
- 只使用按日期对齐的 PnL，禁止累计 PnL 相关。
- 将 PnL 端点的 HTTP 200 空响应视为瞬时限流并有限重试；不得用空数组覆盖有效缓存或绕过提交门槛。
- 保留最终未触碰评价阶段，并披露多重检验风险。
- 真实提交前必须获得明确授权。
- 必须确认 `status == ACTIVE`，HTTP 201 不代表成功。
- 将凭据和私有研究记录排除在版本控制之外。
- 只有聚合、脱敏且经过多次复现的经验才能晋升到公开 references。
